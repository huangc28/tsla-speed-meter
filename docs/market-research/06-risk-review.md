## 重點結論

- 【推論】先完成速度失效處理與安裝安全驗證，再擴大上市；GPS 備援不代表隧道或背景中仍有可靠速度。[S08][s08] [S09][s09] [S12][s12]
- 【事實／推論】美國安裝規則因州而異；台灣禁止行駛中手持操作，固定手機也不能據此宣稱所有用法合法。[S02][s02] [S04][s04] [S05][s05] [S19][s19]
- 【事實／推論】Tesla 已公開 BLE 協定與車輛資料讀取程式；仍須分開評估技術相容性、開源授權與商業契約。[S10][s10] [S11][s11] [S15][s15]
- 【推論】上市名稱宜使用獨立品牌；mirror mode 預設關閉，未完成查核前不宣稱合法、安全或「0.3 秒可讀」。前三項處理順序見下表。[S02][s02] [S15][s15] [S17][s17] [S20][s20]

研究日：2026-10-16。範圍依共同 brief，僅 Part A；未審閱其他成員報告。引註的 URL、發布或更新日期列於「來源」。

評級均為【估計】，指緩解前的產品風險，並非事故率、違規率或下架機率。可能性「高」表示正常使用即可能遇到；「中」表示取決於設定或特定情境；「未知」表示缺乏可靠發生率。影響「極高」涉及人身安全或主要功能失效；「高」涉及下架、法律爭議或重大信任損失。緩解方式均為【推論／建議】，尚未代表已實作。

### BLE 歷史證據能支持到哪裡

- 【事實】Tesla 官方 protocol 文件明載，2023.38 起 Fleet Manager 角色不能經 BLE 傳命令；2024.38 起支援指定旗標的回應加密。[S10][s10] 前者是有範圍的版本行為改變；後者不能直接說成「舊客戶端全面失效」。2023 年版本資訊已逾 2 年。
- 【事實】官方 commit `7457011` 加入 BLE vehicle-data 讀取；因此 brief 所述「社群逆向工程」不宜延伸成「Tesla 從未公開 BLE 資料讀取」。[S11][s11] 是否符合本產品的欄位、更新率與配對方式仍待實車驗證。
- 【事實】issue #279 的 repo collaborator 說明回應大小受 VCSEC RAM 限制，屬 2024 年、逾 2 年資料；#472 在 2026-08-13 有開發者回報，導航目的地資料可能使 `GetDriveState` 回應過大而讀不到速度。[S12][s12] [S13][s13] 後者是當事人回報，未經本團隊重現，也不是 Tesla 官方確認。
- 【缺口】找不到可靠資料證明「某次 OTA 使所有第三方逆向 BLE 車速 app 全面失效」，也找不到可估算每年失效次數或修復天數的資料。雲端 Owner API 的變更、第三方 TPMS 故障不能當成本地 BLE 車速的同一事件。

### 商標執法證據的界線

- 【事實】WIPO D2025-1306 於 2025-05-27 命令移轉涉案網域；其中把含 TSLA 的部分網域認為是可辨識 TESLA 的拼字變體。案件涉及詐騙與惡意註冊。[S17][s17]
- 【推論】省略 E 不是自動安全的命名方式；上述裁決也不能直接判定本 app 必然侵權。
- 【缺口】本輪對 Tesla 第三方 app 商標執法案例，找不到可靠資料可證實「某合法 HUD／車主 app 因名稱而遭 Tesla 要求下架」。網域裁決不是 app 下架案例，其他第三方 app 仍在架上也不是本產品獲授權的證據。

## 假設

- 以 brief 為產品現況來源：GPS 版完成、BLE 在可行性驗證、尚未上架；未把外部 SDK 的能力視為本 repo 已具備的功能。
- v1 為手機輔助顯示，保留原車儀表；不提供車輛控制、超速警示、速限、CarPlay／Android Auto 或實體反射膜。若變更，需重新評估。
- 「0.3 秒」是待驗證的產品目標，找不到本產品可支持該數字或事故減少效果的可靠資料。
- 先以成年人、私人 Model 3／Y 為範圍；未覆蓋商用車、未成年駕駛或改裝審驗全部要求。
- 本輪無法量化拒審、被告、韌體失效及保險費率；不以競品存在推估低風險。
- 美國加州官方法條網站回傳 403，因此 §26708 使用 2026-01-01 的 FindLaw 重刊；§23123.5 另比對 NHTSA 託管的加州官方計畫附件。上架前仍須確認最新州法與適用解釋，未完成其他州即不聲稱全美合法。
- Tesla 公開技術文件與 Fleet 商業契約分開看待。本報告不判定純本地 BLE 必然受 Fleet Agreement 約束，也不判定沒有約束；是否註冊、接受條款、採官方註冊金鑰流程及混用 Fleet API 都是查核事項。
- 台灣個資法官方頁列有 2025-11-11 修正、部分條文待施行；本報告使用的 §8、§19、§20 不在該次待施行變更清單中，不把待施行修文當現行要求。[S21][s21]

## 待驗證問題

### 需要訪談真實車主及觀察使用

- 美國與台灣分別訪談：手機實際裝哪裡？是否遮住行人、路口或原車畫面？不同身高能否沿用同一安裝位置？
- 車主在夜間、下雨、戴偏光眼鏡時，直視與鏡射各有哪些不可讀情境？鏡射是否迫使車主加膜或調亮？
- 是否願意新增唯讀車鑰匙、了解撤銷方法？與 Tesla 官方手機鑰匙、其他乘客手機並用時是否出現問題？
- BLE 失效改用 GPS 時是否看得懂來源差異？願意接受何種失效提示、支援車型限制及退款方式？
- 行駛中會否想切換模式、調亮度或重新連線？實際觀察能否在出發前完成，而非只問「會不會分心」。

### 訪談無法取代的查核

- 主管機關／各地法務：具體手機支架與自然鏡射安裝圖是否合規？其他州、地方與玻璃貼膜規則為何？
- Tesla 契約／授權查核：選定 BLE 配對與資料讀取方案適用哪些條款？實際能否取得足夠的唯讀權限？
- 實車與人因測試：速度資料更新、延遲、凍結偵測、來源切換、鏡射視野，以及 0.3 秒可讀性。
- 保險與商店：保單是否排除車用或人身損害？具體權限與示範流程能否通過審核？本輪沒有答案，不以訪談猜測。

- 【法律假設】法律適用依具體設計、交易與市場判斷；不以免責、免費或競品存在推定合法。本節是風險處置建議，未完成產品認證或個案法律結論。未查明的通路採不預支觸及、未驗證的贈品採移除，無須阻塞其他研究。

### 建議措辭與 H9 測試界線

【建議文案，僅於產品實際符合時採用】

> 本版本不提供方向燈、盲點、Autopilot／FSD 接手警告或下一轉彎指示。我們目前支援的車輛藍牙資料介面未提供這些顯示所需的完整即時資料；部分資料有其他雲端或外接硬體方案，但本版本不支援。請依原車顯示、警告與實際路況判斷，本 app 不取代原車安全功能。

這句以**本版未提供**為主，不斷言 Tesla 的全部政策，也不承諾未整合硬體即可補齊。必要相容性說明可另寫「本 app 為獨立開發，非 Tesla 官方產品，與 Tesla 無隸屬或贊助關係」；這只降低混淆，不授予商標權、不保證過審或免責。10 示意圖的「● TESLA」建議改「車輛藍牙」，不要使用 Tesla logo 模仿官方介面。商品名稱、關鍵字與截圖仍按 Part A/B 審查；不是禁止一切必要的描述性提及。[Apple][c31]

【建議付費文案，待實車通過後】

> 藍牙連線及車輛資料有效時，讀取車輛回報的車速、檔位與電量，不依賴手機 GPS 估算車速。數值可能因更新時間與顯示取整而有差異；可用性依支援車型、韌體與連線狀態而定。失效時會標示；僅在有有效 GPS 讀值時提供速度備援。停車車況以本版本列出的功能為準。

【推論】這可表達資料來源價值，但不能接上「所以隧道永遠不中斷／更安全／更快」。09 的 270–500 ms 是他人往返回報，1–2 Hz 是實驗起點；pmf → gtm 的「09 量到 BLE 與 GPS 同級」應改為「09 提出估計，尚未量測本產品」，也不能反向宣稱兩者性能已證實相等。[C09](09-data-feasibility.md)

【建議 H9／H16 修正】兩組固定相同流量來源、資格、觀察期與去重口徑，事前選共同指標。例如兩組都量「US$9.99 付款意向確認」，B 額外量免費使用意向，並把留 email 與付費意向分開。每組 ≥300、A 點擊 ≥3% 等是 10 的事前門檻，不是支付實績；報告分子／分母與不確定性，不以 A 購買點擊比 B 免費留信率的一半推成付費模型勝出。email 自願、告知用途與刪除方式；在產品外的研究頁測試，不把尚未交付的假門當正式商店購買功能。實際收款另完成商店權益驗收，延期功能及既有免費／買斷權益不得藉 A/B 任意撤回。[C10](10-data-priorities.md) [Apple][c31] [B20][b20]

### 假設、未解事項與來源

- 【假設】v1 首發仍為零外接硬體、GPS 備援＋待驗 BLE；v1.x 摘要／警示未提前承諾。只審查提案，沒有修改／重測程式；舊 Part A/B 保留為研究紀錄，新範圍須另滿足本節條件。
