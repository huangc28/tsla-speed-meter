## 使用者喜歡 Dashla 的地方

1. **中間一個圓形速度表**,圓環上有小圖示顯示狀態:前車廂開 / 關、後車廂開 / 關、超速提醒、其他警告。
2. **左右兩側各一個面板**,上下滑動換內容:
   - 胎壓;
   - 行程:開了多久、多遠、平均速度、這趟用的電;
   - 正在播的歌;
   - 地圖或導航。
     - Dashla 2.3.2 是在手機上自己用 Apple 地圖導航,從車上只拿預計到達、剩下距離、到達電量。它不能把目的地傳給車,所以手機和車的路線可能不同(早期評論就在抱怨這點)。
     - **我們只畫「車上導航的摘要」**:目的地、還要幾分鐘、幾公里、到達電量。車上沒在導航時要有空狀態。我們不做手機導航。

截圖裡還有:
- 圓裡數字上方的 `P R N D`;
- 左下電量 % / 續航,右下總里程;
- 上方一條:時間、天氣、車內溫度、連線、手機電量、音量、夜間模式、設定;
- 右邊緣幾顆浮動圓鈕:主題、字級、音樂。

## 交付

1. **先調查**(memory「先調查再畫」):4–6 個真實參考,附連結。
   - 一定要有:Dashla、DriveCluster(App Store id6762794279)、Tesla 車上中控的儀表區。
   - 另外 1–3 個量產車或電動車的駕駛顯示,有側邊小工具的,例如 Rivian、Polestar、BMW iDrive 8、Mercedes MBUX。
   - 每個寫一行「值得借的做法」、一行「要避開的做法」。
2. **2–3 個明顯不同的方向**,畫在現行設計旁邊。現行是 `frames/landscape/S04-b-ble.png` 和 `S06-b-parked-ble-p.png`(量表 C),標「現行(保留參考)」。每個方向畫三張:
   - **行駛,車輛藍牙**:有 `P R N D`、電量 / 續航,圓環上亮一個圖示(後車廂開著);
   - **行駛,GPS 備援**:沒有車子資料,側面板只放 GPS 給得出來的東西;
   - **停車(P)**:側面板顯示胎壓和行程。
3. 每個方向一段短說明:
   - 側面板預設放什麼;
   - 怎麼滑;
   - 行駛中面板會怎樣。
4. 最後一段比較和建議(一段話),加上新增檔案清單。

## 限制

- **畫布:** 844 × 390 橫式(iPhone 14/15),SafeArea 加 16 邊距,和 `frames/landscape-mockups.html` 一樣。沿用 `DESIGN.md` 的 token 和槍灰色風格。哪個方向刻意改 token,要寫出來。
- **資料**(`docs/market-research/09-data-feasibility.md`):
  - 車輛藍牙拿得到:車速、檔位、電量 %、續航、胎壓、車門 / 前車廂 / 後車廂 / 車窗、正在播的歌名和歌手(沒有封面、沒有歌詞)、馬力輸出、車上導航摘要(目的地、分鐘、英里、到達電量;沒有轉彎箭頭)。
  - **拿不到,不要畫:** 方向燈、盲點、Autopilot / FSD 狀態。
  - **超速:** 依道路速限要地圖資料,已延後(#2)。使用者可以接受自己設一個門檻(例如 110)。這一輪只畫圖示的狀態。
- **安全:**
  - 車速數字是唯一主角,**不能為了塞面板縮小**,也不能被擠動位置(L35、L39 的字高下限照舊)。
  - 面板最好行駛中不用去碰:例如只在 P 檔能滑,或行駛中自動切到預設內容。每個方向寫出它的做法。
  - 歌詞、地圖只在停車時出現,除非某個方向有理由不這樣做。
- **保留舊選項**(memory「保留沒選的設計」):
  - 不改、不覆蓋 `docs/design/frames/` 裡任何現有檔案。
  - 新東西放在**新檔** `docs/design/frames/main-redesign.html`,PNG 放在**新資料夾** `docs/design/frames/main-redesign/`。
  - 選定以後,沒選的方向標「未選(保留參考)」。
- **工程同時在做:** #48(排檔那一行)和 #49(電量 / 續航)照現在的版面在做。規則都在 HUD engine 裡,選定新方向後會跟著搬過去。

## 共同規則(和 `00-brief.md` 相同,這一輪的寫入範圍如下)

這些規則優先於你從 `AGENTS.md` / `CLAUDE.md` 繼承的一般規則(例如「先進 plan mode」「先問再做」)。

1. **不要卡住**:不要進 plan mode,不要問使用者,不要等確認。不確定就做合理假設,寫進輸出檔的「假設」段落,必要時在 `team-board.md` 留言,然後繼續。
2. **自己做**:不要開 subagent 或 workflow。
3. **只寫自己的檔案**:
   - `ux` 只寫 `07-main-redesign-survey.md`;
   - `safety` 只寫 `08-main-redesign-safety.md`;
   - `visual` 只寫 `frames/main-redesign.html` 和 `frames/main-redesign/`;
   - 大家都可以在 `team-board.md` 檔尾追加。
   - 不要改程式碼、`DESIGN.md`、`PRODUCT.md`、`tsla-speed-meter.pen` 或其他檔案。
   - 不要 git commit,不要 `git checkout` / `git switch`。
4. **文案守 06 Part C**:不寫「跟車上一模一樣」「隧道不中斷」「比 GPS 快」「原廠沒開放手機、一定要接線」「不破保」。畫面上的字都要給繁中和英文。
5. **安全原則**:車速是唯一主角。行駛中不放長文字、設定操作、購買畫面。狀態不能只靠顏色表示。
6. **證據**:引用研究報告時標檔名和章節,例如 `[09 §BLE]`、`[06 C09]`。外部來源附 URL 和查詢日期。
7. **語言**:繁體中文(台灣用語),專有名詞保留英文。精簡,以表格和條列為主,開頭放 5 行以內的「重點結論」。
8. **完成時**:回覆的最後一行只寫 `DONE: docs/design/<你的檔名>`(visual 寫 `DONE: docs/design/frames/main-redesign.html`)。

`team-board.md` 的格式照 `00-brief.md`。
