# 第十七輪 brief:把己「ATELIER」畫到接近參考圖(2026-11-08)

## 背景

- 產品:原生 Swift 的 iPhone 橫式車速 HUD,給車主自己的 Tesla 用。車速、檔位、電量、車門 / 車廂、導航來自車輛藍牙;沒車速時用手機 GPS。
- 第十六輪(`00-brief-speed-meter.md`、`00-summary-speed-meter.md`)做了比較頁 `frames/prototype-speed-meter.html`,甲到戊五個速度表版本,車主還沒選。
- 車主 2026-11-08 寫了 **`DESIGN_v2.md`**(repo 根目錄):新方向「ATELIER — Tesla Edition」,整個畫面的設計交接,附參考圖 **`docs/atelier-reference.png`**(直式 + 橫式各一張)。車主決定先做成 HTML 變體看,lead 加了第六個版本 **己「ATELIER」**(`?variant=f`,程式在頁面裡的 `FF` / `placeF` / `carF` / `drawF`;裁定 L94)。
- **這一輪的起點**:車主看了己,說「細節和參考圖差太遠」。lead 承認:己只把版面和狀態做對,車圖是十幾個形狀的示意、弧和背景平塗、字的層次粗。車主要求:**照參考圖的細節做到八成像**,而且**另做一個「展示版」**,數字用細字、縮回參考圖的比例,暫時不管數字大小的規定,讓他看純視覺效果;守規定的己保留對照。車主特別交代:**注意細節,否則不會滿意**。
- 兩個事實不變:車子藍牙沒有「下一個路口」(只有目的地、剩餘時間 / 距離、抵達電量),所以導航橫條不畫「450 m 右轉」;這頁只有橫式框,直式不畫。

## 目標

1. **己(`f`)改到接近參考圖橫式那張的質感**,但守第十六輪的安全底線(見下)。
2. **新增庚「己 展示版」(`?variant=g`)**:和己同一套程式、同一個版面,只有速度表照參考圖的比例和字重(數字細、小),頁面上標明「展示版:數字沒守高度和筆畫的下限,只看視覺」。
3. 一張**對照圖**,讓車主能把參考圖和我們的畫面放在一起看細節。
4. 一輪細節批評 + 安全審查,再一輪修訂。

## 參考圖裡要對到的細節(visual 逐項對,寫進 `12` 的檢查表)

打開 `docs/atelier-reference.png` 真的看(用 Read 看圖;要看細節就先用 Python PIL 裁切放大再看)。橫式那張在右半邊。

- **車(最重要)**:俯視 Model Y,白銀車身,光從上方來:引擎蓋和肩線有高光、車身邊緣有暗一階的輪廓、側面有漸層;全景玻璃車頂深色、帶一道柔和的反光漸層;擋風玻璃下緣和後窗的分界清楚;兩側後視鏡(有深色鏡面);車門縫線;輪拱在側邊露出深色;車頭燈、車尾燈是細細的一條(尾燈可以是很暗的紅,不能搶眼);車底有柔和的環境陰影。比例約寬 1 : 高 2.05。全部用 SVG 向量畫在頁面裡(漸層、濾鏡可以用),不用點陣圖、不用參考圖裁下來的車。六處開口(左前、右前、左後、右後門、前車廂、後車廂)要能分別亮:開著 = 該處變紅 + 門扇 / 掀蓋往外開,844 大小下一眼看得出「哪一扇開了」。
- **弧**:細、低對比、**兩端淡出**(參考圖的弧端是漸隱的,不是平頭);弧和背景的亮度差照參考圖量(用 PIL 取參考圖弧線和背景的像素值,換成我們色票的等效值)。
- **數字**:參考圖是細字(接近 SF Pro Display Light / Thin),等寬數字,字和弧的比例(弧直徑 ÷ 數字高)、數字和 `km/h`、`P R N D` 的間距比例,都量出來寫下。己用能守住「直筆 ≥ 9 px」的最細字重(系統字是可變字重,試 300 / 350 / 400 各量「1」的直筆);庚照參考圖的字重和比例。
- **`P R N D`**:參考圖字距很寬、熄的字很暗、亮的字白而粗一點;量字距和字級的比例。
- **電量列**:參考圖的電池圖示是圓角外框 + 實心電量 + 小凸點,`78%` 比 `382 km` 亮一階、中間一個「·」;我們用 `72% · 315 km`。
- **車門列**:參考圖是「車身輪廓 + 一扇打開的門」的線條圖示 + 文字 `All closed`;我們用「全部關閉」,開著時換紅色圖示 + 字,一處一列。
- **導航橫條**:暗面、大圓角、沒邊框;左邊白色箭頭、`450 m` 粗大、街名細小;**右端有一小段路的示意和藍色定位箭頭**(DESIGN_v2 §7 允許藍色用在路線 / 車輛位置,整個畫面只有這裡用藍)。我們的字是 `12 km`、`剩餘 18 分`、`台北車站`、`抵達時約剩 64%`,排法照參考圖的層次。
- **背景**:參考圖不是純平黑,有很淡的暈(中間略亮)和邊角略暗;仍然近黑(DESIGN_v2 §2 允許「restrained dark gradient」)。
- **上排**:時間、來源圖示、設定齒輪照 DESIGN_v2 的次字色;來源圖示的語意色(藍牙綠、GPS 琥珀)保留。
- **字的層次**:參考圖每一層的字級、字重、顏色都量(用 PIL 取色),對到 DESIGN_v2 的色票:主字只給車速和目前檔位(L91 例外);`72%`、導航距離、目的地用 `#CDD2D9`(DESIGN.md 的 text.secondary,第十六輪裁定過,不是主字);其他次字 `#92969C`;熄的 `#4F5359`。

## 己要守的規則(庚不守數字的兩條,其他照守)

- 車速是唯一主角;狀態不只靠顏色(紅 + 形狀 + 文字);開車畫面只有車速和目前檔位用主字色。
- 車況開著用紅;自訂門檻不用紅、不閃(己現在是弧變亮變粗 + 上方小錶,可以改,但要中性)。
- 其他東西離車速數字墨跡 ≥ 9;等寬數字,同位數時沒變的數字不左右移。
- **數字墨跡高 ≥ 105、「1」直筆 ≥ 9**(L39、R7-01)。**庚只豁免這兩條**,而且頁面要標明。
- 沒有車子的資料時(GPS 備援):不畫右欄和導航、不標任何開口、車變暗(不捏造車況);沒有車速:「—」+ 「車速暫不可用」。
- 導航只放車子給得出的資料。

## 共同規則

這些規則優先於你從 `AGENTS.md` / `CLAUDE.md` 繼承的一般規則(例如「先進 plan mode」「先問再做」)。

1. **不要卡住**:不要進 plan mode,不要問使用者,不要等確認。不確定就做合理假設,寫進輸出檔的「假設」段落,必要時在 `team-board.md` 留言,然後繼續。
2. **自己做**:不要開 subagent 或 workflow。
3. **只寫自己的檔案**:
   - `visual` 只寫 `frames/prototype-speed-meter.html`、`frames/prototype-speed-meter/` 裡的檔案、`12-atelier-visual.md`;
   - `ux` 只寫 `13-atelier-critique.md`(可以在 `frames/prototype-speed-meter/critique/` 放自己裁的對照圖);
   - `safety` 只寫 `14-atelier-safety.md`;
   - 大家都可以在 `team-board.md` 檔尾追加;lead 要你寫時,也可以寫 `handoff-<你的名字>.md`。
   - 不要改程式碼、`DESIGN.md`、`DESIGN_v2.md`、`00-rulings.md`、第十六輪的檔案、`tsla-speed-meter.pen` 或其他檔案。
   - 不要 git commit,不要 `git checkout` / `git switch`。
4. **證據**:量到的值寫出怎麼量的(哪張圖、幾倍、哪個區域);外部來源附 URL + 日期;標明事實、估計或推論。
5. **上網**:這一輪不需要;真要查(例如 SF Pro 的字重名稱)總共 10 分鐘、10 頁以內。
6. **語言和長度**:繁體中文(台灣用語),專有名詞保留英文。表格和條列為主,開頭放 5 行以內的「重點結論」。
7. **完成時**:回覆的最後一行只寫 `DONE: <你的輸出檔路徑>`(例如 `DONE: docs/design/12-atelier-visual.md`)。之後的修訂也一樣結尾。
8. **邊做邊存**:開始前先建好輸出檔,放所有章節標題,標題下一行寫 `Status:`。每完成一節就存檔並更新這一行。中途停下時,接手的人從這一行開始。
9. **未選的保留**:甲到戊和舊檔案都不刪、不改名。
