# 第十六輪 brief:速度表不要像 Dashla(2026-11-07)

## 背景

- 產品:原生 Swift 的 iPhone 橫式車速 HUD,給車主自己的 Tesla 用。車速、檔位、電量、車門 / 車廂、導航來自車輛藍牙;車輛藍牙沒車速時用手機 GPS。
- 現在 app 裡的主畫面是方向 A「雙翼」:`DESIGN.md`「Main screen — direction A」,HTML 母稿 `frames/main-redesign-a2.html` 的 ①(開車・連著車)。app 已照它做完。
- 經過:2026-10-25 車主決定「自用 + 學習」,想借 Dashla 的做法(圓形錶、環上狀態圖示、左右可滑的面板)。第十二輪 `07-main-redesign-survey.md` 提了 A / B / C 三個方向,選了 A,它是三個裡最像 Dashla 的(`07 §3.1`)。
- **這一輪的起點**:車主 2026-11-07 說「現在的 speed meter 有點完全抄 Dashla」,想先看別人的速度表還有哪些做法,再比較幾個不像 Dashla 的方向。
- 以前畫過、沒選的(保留參考,可以當起點,但要說明和它們差在哪):`frames/gauge-variants.html`(第六到八輪的錶)、`frames/main-redesign.html` 的 B「靜行」和 C「單卡」(`07 §3.2–3.3`)。它們是在「借 Dashla」的目標下比較的,現在目標變了。

## 目標

1. 說清楚 A 的速度表**具體哪些地方**讓人覺得像 Dashla(圓環 + 圓盤、環裡的車況圖示、檔位排法、數字和單位的排法…),逐項列。
2. 調查別的速度表怎麼設計(附來源),整理出適合「手機橫放、瞄一眼」的原則。
3. 提三個新方向 乙 / 丙 / 丁,和 A 不一樣,彼此也要**結構上**不一樣(版面、資訊層級、主要的視覺形狀),不能只差顏色或字型。至少兩個**不用圓環**。
4. 做一頁比較頁:甲「目前」(A 原樣)+ 乙丙丁,底下的切換列可以左右切換。
5. 安全審查:瞄一眼看不看得清楚、會不會分心、對比夠不夠。

**範圍:只換中間的速度表**(車主 2026-11-07 選的)。
- 會換的:車速數字、單位、`P R N D`、車況圖示(前車廂、車門、後車廂)、自訂門檻小錶、沒有車速時的樣子、GPS 提示箭頭、超過門檻的表示法。這些可以在中間欄裡重新擺。
- 中間欄:844 寬時,左面板右緣 x 260 到右面板左緣 x 584 之間,y 0–390(上排的來源圖示和時間不動)。
- 不換的:上排(來源圖示、時間、外溫)、左邊行程面板、右邊導航面板、停車畫面。
- 這一輪只畫 844 的白天開車畫面。夜間、667、英文、mph、停車、大字都不畫,但方向文件要寫出各方向在這些情況的風險。

## 哪些規則照舊、哪些不綁

照舊(安全和可讀性底線,新方向也要守):
- 車速是唯一主角;開車時不放長文字。狀態不能只靠顏色。
- 開車畫面只有車速數字用 `text.primary`。車況「開著」用紅色;自訂門檻不用紅色、不閃、不響(L78、L87)。
- 車況圖示、其他東西離車速數字墨跡 ≥ 9(R7-02、L48)。
- 等寬數字,車速變 1 時沒變的那幾位不能左右移(L38、L88 的原則)。三位數墨跡高下限照 L39。
- 色票和對比照 `DESIGN.md`「Color tokens」。

不綁新方向(只屬於 A 的幾何):圓環半徑、圓盤、車況圖示的槽位座標、數字固定 160、`P R N D` 26 px 一格、L74–L88 裡只講 A 位置和大小的部分。新方向自己定這些,寫進方向文件。

## 共同規則

這些規則優先於你從 `AGENTS.md` / `CLAUDE.md` 繼承的一般規則(例如「先進 plan mode」「先問再做」)。

1. **不要卡住**:不要進 plan mode,不要問使用者,不要等確認。不確定就做合理假設,寫進輸出檔的「假設」段落,必要時在 `team-board.md` 留言,然後繼續。
2. **自己做**:不要開 subagent 或 workflow。
3. **只寫自己的檔案**:
   - `ux` 只寫 `10-speed-meter-survey.md`;
   - `visual` 只寫 `frames/prototype-speed-meter.html` 和 `frames/prototype-speed-meter/`;
   - `safety` 只寫 `11-speed-meter-safety.md`;
   - 大家都可以在 `team-board.md` 檔尾追加;lead 要你寫時,也可以寫 `handoff-<你的名字>.md`。
   - 不要改程式碼、`DESIGN.md`、`00-rulings.md`、`frames/main-redesign-a2.html`、`tsla-speed-meter.pen` 或其他檔案。
   - 不要 git commit,不要 `git checkout` / `git switch`。
4. **證據**:重要的說法要附來源(外部:URL + 查詢日期;內部:`檔名 §章節`),並標明是事實、估計還是推論。找不到就寫找不到。
5. **上網**(主要是 ux):總共約 40 分鐘、40 次讀網頁以內。打不開或很慢的頁面直接跳過,同一頁不重試第二次。
6. **語言和長度**:繁體中文(台灣用語),專有名詞保留英文。表格和條列為主,開頭放 5 行以內的「重點結論」。
7. **完成時**:回覆的最後一行只寫 `DONE: <你的輸出檔路徑>`(例如 `DONE: docs/design/10-speed-meter-survey.md`)。之後的修訂也一樣結尾。
8. **邊做邊存**:開始前先建好輸出檔,放所有章節標題,標題下一行寫 `Status:`。每完成一節就存檔並更新這一行,例如 `Status: 完成 1–3;下一步 4;剩 4–6`。中途停下時,接手的人從這一行開始。
9. **未選的保留**:以前的方向和檔案都不刪、不改名;沒選的標「未選(保留參考)」。
